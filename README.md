# 소재창고 v1.1 — 모바일 · PWA 버전

개인 창작자를 위한 아이디어 보관소입니다. 임시 메모 → 아이디어 파편 → 정식 소재 → 작품 프로젝트로 기록을 발전시키며, **모든 기록은 사용하는 기기의 브라우저 안에만 저장**됩니다. 서버·계정·외부 스크립트·분석 도구가 없습니다.

v1.1은 v1.0(단일 HTML)의 기능을 모두 유지한 채 다음을 더했습니다.

- 스마트폰 화면(360px~) 전용 레이아웃: 하단 메뉴, 홈 화면, 전체 화면 편집기, 아래에서 올라오는 창
- 홈 화면에 설치 가능한 PWA(앱처럼 실행), 오프라인 실행, 새 버전 업데이트 안내
- Android 뒤로 가기 대응(창 닫기 → 이전 화면)
- 여러 탭 동시 사용 보호(충돌 시 ‘충돌 사본’으로 양쪽 내용 보존)
- 향후 동기화를 위한 데이터 준비 항목(저장 횟수 `rev`, 기기 ID, 영구 삭제 기록)

---

## 1. 폴더 구조

```
creative-warehouse-v1.1/
├─ index.html              앱 화면
├─ css/app.css             스타일 (v1.0 스타일 + v1.1 모바일 규칙)
├─ js/app.js               앱 전체 로직 (저장·검색·백업·모바일·PWA)
├─ sw.js                   서비스 워커 (앱 파일 캐시 전용, 기록은 다루지 않음)
├─ manifest.webmanifest    PWA 설치 정보
├─ icons/                  앱 아이콘 (192·512·maskable·apple-touch·svg)
├─ _headers                Cloudflare Pages/Netlify용 캐시 헤더 (선택)
├─ .nojekyll               GitHub Pages용 (선택)
└─ tools/serve.ps1         로컬 테스트 서버 (배포 불필요)
```

모든 경로는 **상대 경로**이고, 화면 이동은 `#/inbox`, `#/edit/<ID>` 같은 **해시 주소**를 씁니다. 그래서 서버 쪽 리다이렉트 설정 없이 어떤 정적 호스팅의 어떤 하위 폴더에 올려도 새로고침·바로가기 주소가 깨지지 않습니다.

## 2. 로컬에서 실행하기

### 간단히 보기
`index.html`을 더블클릭해도 동작합니다. 단, `file://`로 열면 **서비스 워커(오프라인 실행·설치)는 동작하지 않습니다.** 브라우저 정책상 지원되지 않습니다.

### 설치·오프라인까지 시험하기
`localhost`는 브라우저가 보안 환경으로 취급하므로 PWA 기능을 시험할 수 있습니다.

```bash
powershell -ExecutionPolicy Bypass -File tools\serve.ps1
```

→ 브라우저에서 `http://localhost:8765/` 열기 (포트 변경: `-Port 9000`)

> 저장소는 **주소(출처)마다 따로** 있습니다. `file://`, `http://localhost:8765`, 배포한 `https://…` 주소는 서로 다른 저장소를 씁니다. 실제로 쓸 주소를 하나 정해 두세요.

## 3. 사용법 (스마트폰)

| 하단 메뉴 | 기능 |
|---|---|
| 홈 | 빠른 메모 입력, 최근 사용한 작품, 즐겨찾기, 최근 수정·작성 기록, 백업 알림 |
| 메모 | 임시 메모 목록 |
| ＋ 새 기록 | 종류를 골라 새 기록 작성 |
| 작품 | 작품 프로젝트 목록 |
| 전체 | 모든 메뉴(파편·소재·즐겨찾기·휴지통·설정·랜덤 소재·앱 설치) |

- **검색**: 상단 돋보기 버튼
- **빠른 메모**: 상단 연필 버튼 또는 홈 화면 입력 칸
- **편집 화면**:
  - 입력하면 약 0.7초 뒤 자동 저장되고, 상단에 저장 상태가 표시됩니다.
  - ★는 즐겨찾기, ⋯ 메뉴에서 고정·AI 분석용 복사·삭제를 할 수 있습니다.
- **장르·태그**: 입력 후 ‘추가’ 버튼, Enter, 또는 쉼표로 추가합니다. 한글 입력 중에는 ‘추가’ 버튼이 가장 확실합니다.
- **뒤로 가기**: Android 뒤로 가기 버튼으로 열린 창·메뉴를 닫고, 이전 화면으로 돌아갑니다. 편집 내용은 이동 전에 먼저 저장됩니다.
- PC에서는 v1.0과 같은 사이드바 화면이 그대로 유지됩니다.

### 홈 화면에 설치
- **Android Chrome**: ⋮ 메뉴 → ‘앱 설치’ 또는 ‘홈 화면에 추가’. 브라우저가 설치를 허용하면 앱의 ‘전체’ 메뉴와 설정 화면에 ‘앱으로 설치’ 버튼도 나타납니다.
- **삼성 인터넷**: ≡ 메뉴 → ‘현재 페이지 추가’ → ‘홈 화면’
- **iPhone Safari**: 공유 → ‘홈 화면에 추가’
- **PC Chrome·Edge**: 주소창 오른쪽 설치 아이콘

설치한 앱과 같은 주소의 브라우저 탭은 **같은 기록**을 씁니다. 설치한 앱으로 실행하면 브라우저에 ‘영구 저장’을 자동으로 요청해, 저장 공간이 부족할 때 기록이 임의로 지워질 가능성을 줄입니다.

## 4. 웹사이트 배포

필요한 것은 위 폴더의 정적 파일뿐입니다(`tools/`는 빼도 됩니다). **HTTPS 주소**여야 설치·오프라인 기능이 동작합니다.

### GitHub Pages
1. GitHub에서 새 저장소를 만듭니다(예: `creative-warehouse`).
2. `creative-warehouse-v1.1` 폴더의 **내용물**을 저장소 최상위에 올립니다. `index.html`이 최상위에 있어야 합니다.
3. 저장소 **Settings → Pages → Build and deployment**에서 Source를 ‘Deploy from a branch’로 하고, `main` 브랜치와 `/ (root)`를 선택합니다.
4. 1~2분 뒤 `https://<계정>.github.io/creative-warehouse/`로 접속합니다.

### Cloudflare Pages
1. Cloudflare 대시보드 → **Workers & Pages → Create → Pages → Upload assets**를 선택합니다.
2. 프로젝트 이름을 정하고 `creative-warehouse-v1.1` 폴더를 끌어다 놓습니다. 빌드 설정은 필요 없습니다.
3. `https://<프로젝트>.pages.dev`로 접속합니다. `_headers` 파일이 자동으로 적용됩니다.

### 기타 HTTPS 정적 호스팅 (Netlify, Vercel, 자체 서버 등)
- 폴더 내용물을 그대로 올리면 됩니다. 하위 경로(`https://example.com/notes/`)에 올려도 됩니다.
- `.webmanifest` 파일을 `application/manifest+json`으로 보내면 가장 좋습니다(대부분 자동 처리).
- `sw.js`와 `index.html`은 오래 캐시하지 않도록 설정하는 것을 권장합니다(`Cache-Control: no-cache`).

### 새 버전을 배포할 때 (중요)
1. 파일을 수정합니다.
2. **`sw.js`의 `CACHE_VERSION`을 반드시 올립니다.** 예: `'v1.1.0'` → `'v1.1.1'`
3. 수정한 파일을 모두 올립니다.

사용자 기기에서는 다음 접속 때 상단에 **‘새 버전이 준비되었습니다 → 지금 업데이트’** 안내가 뜹니다. 업데이트는 다음 순서로 진행됩니다.
- 진행 중인 저장을 먼저 끝냅니다. 저장에 실패하거나 작성 중인 빠른 메모가 있으면 업데이트를 미룹니다.
- 새로고침합니다.
- 이전 버전의 **앱 파일 캐시만** 지웁니다. **IndexedDB의 기록은 건드리지 않습니다.**

`CACHE_VERSION`을 올리지 않으면 이미 설치한 사용자는 계속 이전 파일을 쓰게 됩니다.

### ‘앱 설치’ 메뉴가 안 보일 때
- **구글 앱·카카오톡·네이버 앱 등에서 링크를 누른 경우**: 그 앱 안의 브라우저로 열립니다.
  - 이 화면에서는 설치 메뉴가 없고 파일 저장도 막힐 수 있습니다.
  - 여기서 쓴 기록은 Chrome과 **따로** 저장됩니다.
  - v1.1.1부터는 이 상황을 감지해 상단에 안내와 **‘Chrome에서 열기’ / ‘주소 복사’** 버튼을 보여 줍니다.
- **이미 설치한 경우**: Chrome 메뉴에 ‘앱 설치’ 대신 ‘앱 열기’가 나옵니다. 홈 화면의 ‘소재창고’ 아이콘으로 여세요.
- 앱의 ‘전체’ 메뉴 → **‘앱 설치 방법’**에서 지금 쓰는 브라우저에 맞는 방법을 볼 수 있습니다.

## 5. 데이터 저장 방식과 주의사항

- **저장 순서**: IndexedDB를 먼저 쓰고, 안 되면 localStorage를 씁니다. 둘 다 안 되면 메모리에만 보관하며, 빨간 경고로 저장할 수 없음을 알립니다.
- **서비스 워커와 기록 저장은 별개입니다.** Cache Storage에는 앱 파일만 들어 있고, 기록은 위 저장소에 있습니다.
- 기록은 **기기·브라우저·주소마다 따로** 저장됩니다. **PC와 휴대폰 사이의 자동 동기화는 없습니다.** 같은 사이트에 접속한 다른 사람은 내 기록을 볼 수 없습니다.
- 아래 경우에는 기록이 지워질 수 있습니다.
  - 브라우저의 ‘사이트 데이터 삭제’, 앱 삭제(PWA 제거)
  - 시크릿 창을 닫을 때
  - 저장 공간이 부족할 때 브라우저가 정리하는 경우(영구 저장을 허용하지 않은 경우)
- 그러므로 **자동 저장만으로 영구 보관이 보장되지는 않습니다.** JSON 백업을 정기적으로 만들어 두세요. 기본 7일이 지나면 홈과 설정 화면에서 백업을 권장합니다.
- **여러 탭에서 쓸 때**:
  - 다른 탭에서 저장한 내용은 자동으로 반영되고, 상단에 ‘다른 탭에서도 열려 있습니다’ 안내가 나옵니다.
  - 같은 기록을 두 탭에서 동시에 고치면, 먼저 저장된 쪽이 원래 기록에 남고 나중 쪽은 **‘(충돌 사본)’ 기록으로 따로 저장**됩니다. 어느 쪽도 지워지지 않습니다.
  - 한 탭에서 백업으로 **전체 교체**를 하면, 다른 탭은 낡은 데이터로 덮어쓰지 않도록 저장을 멈추고 새로고침을 안내합니다.

## 6. 백업과 복원 (휴대폰 포함)

- **내보내기**: 설정 → ‘JSON으로 내보내기’를 누르면 다운로드 폴더에 `소재창고_백업_날짜_시각.json`이 저장됩니다.
  - 휴대폰에서 공유 기능을 지원하면 ‘공유로 내보내기’ 버튼도 나타납니다. 드라이브·메신저 등 사용자가 고른 앱으로만 보냅니다.
- **앱 안의 브라우저(구글 앱 등)에서 내보낼 때**: 파일 저장이 막힐 수 있어서 먼저 안내 창이 뜹니다.
  - ‘Chrome에서 열기’로 Chrome에서 내보내는 것이 가장 확실합니다.
  - ‘백업 내용 복사’로 백업 전체를 글자로 복사해 메모장 등에 보관할 수도 있습니다. 복사한 내용은 설정의 **‘붙여 넣어 불러오기’**로 되살릴 수 있습니다.
- **불러오기**: 설정 → ‘JSON 파일 불러오기’ 또는 ‘붙여 넣어 불러오기’
  - 휴대폰에서는 일부 파일 선택기가 `.json` 파일을 회색으로 막는 문제를 피하려고 확장자 제한을 풀었습니다. 내용 검사로 잘못된 파일을 걸러냅니다.
  - 불러오기 전에 기록 개수, 종류별 개수, 충돌 예상 건수를 보여 줍니다.
  - **병합**:
    - ID가 같으면 같은 기록으로 봅니다(사본을 만들지 않음).
    - 최종 수정일이 최근인 쪽을 남기고, 관련 연결은 양쪽을 합칩니다.
    - 현재 기기에만 있는 기록은 지우지 않습니다.
  - **전체 교체**:
    - ‘전체 교체’를 직접 입력해야 실행됩니다.
    - 실행 직전에 현재 데이터를 안전 백업 파일로 자동으로 내려받습니다.
  - 저장은 한 번의 트랜잭션으로 처리되어, 실패하면 기존 기록이 그대로 남습니다.

## 7. v1.0에서 데이터 옮기기

v1.0(`creative_warehouse.html` 파일)과 v1.1은 저장소가 다르므로 **자동으로 옮겨지지 않습니다.**

1. v1.0을 평소처럼 엽니다.
2. 설정 → **‘JSON으로 내보내기’**로 백업 파일을 만듭니다.
3. 휴대폰에서 쓸 거라면 이 파일을 휴대폰으로 옮깁니다(메일·메신저·클라우드 드라이브·USB 등).
4. v1.1 사이트 또는 설치한 앱에서 설정 → **‘JSON 파일 불러오기’**로 그 파일을 고릅니다.
5. 미리보기에서 개수를 확인하고 ‘병합 실행’을 누릅니다. 처음 가져오는 경우라면 병합과 교체의 결과가 같습니다.
6. 가져온 기록이 검색되고 편집되는지 확인한 뒤 계속 사용합니다.

호환성:
- v1.1 백업도 스키마 버전 1을 그대로 씁니다. 그래서 **v1.1에서 내보낸 파일을 v1.0에서도 불러올 수 있습니다.**
- 이때 v1.1에서 새로 생긴 `rev`·`updatedBy`·`tombstones` 항목은 v1.0이 무시합니다.

## 8. 향후 동기화를 위한 구조

v1.1은 서버에 아무것도 보내지 않습니다. 대신 다음을 준비해 두었습니다.

| 항목 | 위치 | 용도 |
|---|---|---|
| `rev` | 각 기록 | 저장할 때마다 1씩 증가합니다. 저장 시 저장소의 값과 비교해 충돌을 감지하며, 같은 방식을 서버 동기화에 그대로 쓸 수 있습니다. |
| `updatedBy` | 각 기록 | 마지막으로 저장한 기기의 무작위 ID입니다(개인정보 아님). |
| `meta.deviceId` | 설정 데이터 | 이 기기의 무작위 ID입니다. |
| `meta.tombstones` | 설정 데이터·백업 | 영구 삭제된 기록의 ID와 시각만 남깁니다(내용 없음). 다른 기기에 삭제를 전파할 때 씁니다. |
| 저장소 어댑터 | `js/app.js` | `loadAll / getRecords / putRecords(rev 검사) / deleteRecords / putMeta / replaceAll` 인터페이스입니다. 클라우드 어댑터를 같은 모양으로 추가할 수 있습니다. |
| 충돌 처리 | `resolveConflicts()` | ‘먼저 저장된 쪽 유지 + 다른 쪽은 사본’ 정책입니다. 동기화에도 그대로 적용할 수 있습니다. |

## 9. 테스트 결과

로컬 서버(`http://localhost`)에서 Chromium 기반 브라우저(Claude 데스크톱 앱의 내장 브라우저)로 직접 실행했습니다. 화면 크기와 터치 기기 모드는 이 브라우저의 기기 에뮬레이션으로 확인했습니다.

## 10. v1.2 개선 제안

1. **선택형 동기화**: 사용자가 직접 연결하는 방식입니다. 예를 들어 본인의 Google Drive나 WebDAV에 암호화된 백업을 올리고 받는 형태로, 위 `rev`·`tombstones`를 사용합니다.
2. **자동 백업 알림 강화**: 정해진 주기마다 ‘공유로 내보내기’를 바로 띄워 주는 단축 동작을 둡니다.
3. **충돌 사본 비교 화면**: 원래 기록과 사본을 나란히 보고 문단 단위로 합치는 화면을 만듭니다.
4. **편집 기록(버전) 보관**: 기록마다 최근 N개 버전을 보관해 실수로 지운 문단을 되살릴 수 있게 합니다.
5. **관계 시각화**: 작품 프로젝트 중심으로 연결 관계를 그리는 지도를 추가합니다(v1.0에서 제외한 항목).
6. **Markdown 미리보기**와 **장면 단위 정렬**(에피소드·장면 순서를 드래그로 바꾸기)을 추가합니다.
7. **접근성 점검**: 화면 낭독기, 큰 글꼴 설정에서 실기기 점검을 합니다.
